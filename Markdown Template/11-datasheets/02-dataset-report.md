## Preprocessing/ Cleaning/ Labeling

Dataset creators should read through these questions prior to any preprocessing, cleaning, or labeling and then provide answers once these tasks are complete. The questions in this section are intended to provide dataset consumers with the information they need to determine whether the "raw" data has been processed in ways that are compatible with their chosen tasks. For example, text that has been converted into a "bag of words" is not suitable for tasks involving word order.

| Question | Answer |
|---|---|
| Was any preprocessing/cleaning/labeling of the data done (for example, discretization or bucketing, tokenization, part-of-speech tagging, SIFT feature extraction,removal of instances, processing of missing values)? If so, please provide a description. If not, you may skip the remaining questions in this section. | Yes, in three steps. No labelling was done. **1. Format conversion.** The downloaded files were saved as `.docx`; the character encoding of one file was repaired. **2. Extraction and cleaning** (`extract.py`). Each Word file is read from start to end, and one clean UTF-8 text file per text is written, with one paragraph or one table row per line. Tables inside the text are kept. Removed: footnotes and footnote markers, the notes block and the amendment-history table at the end of each text, and the link lines to annexes that are not in the text. **3. Chunking** (`chunk.py`). The clean text is split at article headers into one chunk per unit, and the metadata is attached. Amendment notes (950 in total) are taken out of the text and stored in the `amendments` field. Units left with no content after this, that is, repealed articles and one repealed annex (78 units), get no chunk. |
| Was the "raw" data saved in addition to the preprocessed/cleaned/labeled data (for example, to support unanticipated future uses)? If so, please provide a link or other access point to the "raw" data. | Yes, every stage is committed in the team repository (https://github.com/barissaka/chunky-502): the source files in `data/legal/word/`, the clean text in `data/clean/`, and the chunks in `data/chunks/chunks.jsonl`. The files as first downloaded, before they were saved as `.docx`, are not kept; the download addresses are in the register. |
| Is the software that was used to preprocess/clean/label the data available? If so, please provide a link or other access point. | Yes, in the same repository: `src/chunky/extract.py` and `src/chunky/chunk.py`, with the check notebooks in `notebooks/`. They run with Python 3.12, `python-docx` 1.2.0 and `pyyaml` 6.0.3, as pinned in `pyproject.toml`. |
| Any other comments? | The pipeline is described in section 5 (Data pipeline) and decision AD-08 (chunking) of the [System Architecture Design Document](../11-system-architecture-design-document-local.md).
